# Store Supply Forecast

**How much of each item will each store sell over the next 4 weeks, how sure are we, and how much should we stock?**

This project forecasts weekly unit sales for every item in the three Texas stores of the Walmart M5 dataset (TX_1–TX_3). It turns the forecasts into order quantities and flags the item-stores a planner should look at, all in a Streamlit planning app with an Excel export. Every model was tested on a rolling-origin backtest against simple baselines. Where the model doesn't beat them, the results below say so.

## How it works

1. **Data** (`forecast.data`): M5 daily sales, aggregated to Walmart weeks per item × store. Weeks before an item's first price are treated as "not yet listed", not as zero sales, and the Christmas closure is marked.
2. **Backtest** (`forecast.backtest`): 4 forecast origins, 4 weeks apart, at the end of the data, each forecasting 1–4 weeks ahead. Only time-based splits are used: a training row's target week must be on or before the origin.
3. **Features** (`forecast.features`):
   - lags and rolling statistics that use only sales up to the origin
   - prices, events and SNAP days for the target week, which are known in advance
   - every feature has a leakage test
4. **Models** (`forecast.models`):
   - global gradient-boosted models (scikit-learn `HistGradientBoostingRegressor` with Poisson loss, and XGBoost), one model per horizon
   - P50 and P90 from quantile loss
   - baselines: naive, seasonal naive, 4-week moving average
5. **Inventory** (`forecast.inventory`): a simulation with weekly review, 1-week lead time and lost sales. The order-up-to level is P90 for the next 2 weeks. It compares baseline-driven and model-driven orders at equal fill rate.
6. **Exceptions and export** (`forecast.exceptions`, `forecast.export`): flags for forecast drift, projected stockouts and sudden zero-sales runs, each with a plain-language reason. The Excel workbook uses live order formulas.

Every modeling choice, with the alternatives considered, is in [`docs/decisions.md`](docs/decisions.md). The notebooks in [`notebooks/`](notebooks/) tell the story with charts.

## Caveats

- **Sales are not demand.** M5 has no inventory data, so a week with zero sales may have had no stock. The simulation uses sales as demand, which understates true demand.
- **Stock on hand in the app is simulated.** It comes from the model-driven policy, not from real inventory.
- **The order-up-to level adds two weekly P90s.** This overstates the true 2-week P90 slightly, so both policies carry a bit of extra safety stock.
- **The app plans from the last backtest week.** The 4 weeks after it are in the data, which shows forecast and actual side by side but isn't a true future forecast.

## How to run

Requires Python 3.11+. The setup below uses Miniconda for Python itself; all packages come from `requirements.txt`.

```bash
conda create -p ./.venv python=3.11 -y
conda activate ./.venv
pip install -r requirements.txt

# macOS only: XGBoost needs the OpenMP runtime
conda install -p ./.venv llvm-openmp -y

streamlit run app/streamlit_app.py   # the app runs on the committed outputs
pytest -q
```

To rebuild everything from the raw data:

```bash
python -m forecast.download     # M5 raw files -> data/raw/
python -m forecast.data         # -> data/processed/tx_weekly.parquet
python -m forecast.backtest     # baselines -> reports/
python -m forecast.models       # models (the slow step) -> models/, reports/
python -m forecast.inventory    # simulation -> reports/
python -m forecast.exceptions   # flags and order plan -> data/processed/
python -m forecast.readme       # results section of this README
```

## Data

This project uses the **M5 Forecasting** dataset: daily unit sales of Walmart products, with prices and a calendar of events and SNAP days. Credit goes to **Walmart**, which provided the data, the **M5 competition organizers** (University of Nicosia, MOFC), and **Kaggle**, which hosted the competition. Raw data is downloaded by a script (from the Zenodo mirror, CC BY 4.0) and is not committed to this repo.
